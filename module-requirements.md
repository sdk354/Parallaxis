## Deliverables, in order

Proposal → PID → Interim Report → Research Abstract → Final Report → Poster →
Presentation → Live Demo / Video.

The Student Progression Report tracks **14 supervisory meetings** plus signed
approval of: Proposal, PID, Interim 01, Interim 02, Research Abstract, Final
Submission. Each meeting needs a Meeting Minutes sheet (date, items discussed,
items to complete before next meeting, both signatures).

## Proposal template — max 2 pages

Problem Statement · Proposed Solution · Objectives & Deliverables · Target Users ·
Core Features · Technologies to be Used · **Novelty** · Timeline & Milestones
(a four-phase table).

## Stated expectations for a high grade

Meet the supervisor regularly · read research papers weekly · **keep a detailed
development log** · **use Git for version control** · test and evaluate
thoroughly · write continuously rather than leaving the dissertation to the end ·
start early.

## What this changes for Parallaxis

**1. There is a publication requirement.** Research Paper Acceptance is 10 marks
and appears nowhere in the April planning docs or `scope-decisions.md`. A
Research Abstract is also a tracked deliverable in its own right. This needs a
target venue and a submission deadline working backwards from it — acceptance is
not something that can be arranged in the final month.

**2. The prototype carries the coursework.** Final Product is 60 of 100
coursework marks, against 20 for the thesis. The bias toward a working artefact
over written volume is heavier than the earlier planning assumed.

**3. Panel Q&A is 25 marks — the largest single presentation criterion.** The
"defensible in a viva" reasoning recorded throughout `ui-design.md` maps directly
onto this. Decisions with recorded rationale (why perspectives are never
colour-coded, why the severity ramp is single-hue, why displacement encoding was
rejected) are exactly the material this criterion rewards. Keep writing them down.

**4. Presentation is 40% of the whole module.** Roughly two fifths of the grade
does not depend on the code at all.

**5. Git is an explicit expectation and is not in place.** The Parallaxis
directory is not a repository. This is the cheapest outstanding item on the list
and it also produces the "detailed development log" the same slide asks for.

**6. Evaluation is expected, not optional.** "Test and evaluate thoroughly" is
listed as a grade requirement, which settles the evaluation-methodology question
that `scope-decisions.md` had open. What form it takes still needs the
supervisor's steer.
